# Two-Stage Short-Horizon Diffusion Navigation for TurtleBot3

A TurtleBot3 Burger navigates cluttered indoor spaces with a small diffusion
policy trained by imitation from an A* expert. A classical planner hands the
policy a subgoal about 1.2 m ahead, and the policy writes every waypoint the
robot follows. Inference runs on a desktop CPU over a wired tether.

The system was compared with a single-stage version of the same network (no
planner) and with a Dynamic Window Approach (DWA) baseline.

## Results

**Simulation:** 40 unseen BARN worlds, 160 trials per model at each rate.

| Model | 2 Hz | 3 Hz | 4 Hz |
|---|---|---|---|
| Two-stage diffusion | 83.1% | 87.5% | 81.9% |
| Single-stage diffusion | 33.1% | 41.9% | 33.8% |
| DWA | 3.8% | 6.2% | 15.0% |

**Real robot:** a colour-search task with 31 counted runs in one room. The
two-stage system found every target in 13 of 15 runs, and the single-stage
system in 5 of 16. This compares two complete systems (seeking against
wandering), so the simulation numbers are the cleaner test of the planner.

## Getting started

Requires Ubuntu 22.04, ROS 2 Humble, Gazebo Classic and the standard TurtleBot3
packages in `~/turtlebot3_ws`. Real-robot runs also need the fields listed in
[TODO.md](TODO.md).

```bash
cd pathfinding_algorithms
rosdep install -r --from-paths . --ignore-src -y --rosdistro humble
source /opt/ros/humble/setup.bash
colcon build --symlink-install
capstone/setup_venv.sh
```

Add these to your shell profile, with `<repo>` replaced by your clone's path:

```bash
export TURTLEBOT3_MODEL=burger
export LDS_MODEL=LDS-02
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
export CYCLONEDDS_URI=file://<repo>/pathfinding_algorithms/config/cyclone_config.xml
```

BARN worlds, expert data and trained checkpoints are too large to track, so
they are regenerated by script. See
[capstone/README.md](pathfinding_algorithms/capstone/README.md#reproducing-the-pipeline).

## Running

`run.sh` starts everything an algorithm needs. Ctrl-C tears it all down, and on
the real robot it stops the wheels and verifies they have stopped.

```bash
cd pathfinding_algorithms

# Simulation, no robot needed
./run.sh lidar --sim                         # DWA + Cartographer
./run.sh camera --sim                        # camera-fused DWA
./run.sh nav2 --sim                          # Nav2; click a goal in RViz
./run.sh policy --sim                        # diffusion policy wanders and maps
./run.sh policy-two-stage --goto 0 6 --sim 20               # drive to a point
./run.sh policy-two-stage --3_color_test --sim 20           # colour search

# Real robot: same commands without --sim
./run.sh lidar
./run.sh policy
```

Options: `--headless`, `--no-rviz`, `--map <yaml>`. The world after `--sim` can
be `turtlebot3_world`, `house`, `empty`, a BARN index or a `.world` path.

Every lidar and camera run saves its map under `maps/`, and `run.sh nav2 --map
<yaml>` navigates on one later.

## Testing

```bash
cd pathfinding_algorithms
python3 tests/run_tests.py --list
python3 tests/run_tests.py -gazebo_sim       # all three stacks in Gazebo
python3 tests/run_tests.py -capstone_smoke   # BARN world, bumper, expert episode
capstone/.venv/bin/python -m pytest capstone/tests
```

If processes are left behind, `pathfinding_algorithms/tools/kill_all.sh` stops
every ROS process on the PC and the robot.
